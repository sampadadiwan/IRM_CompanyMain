Data & Integrations

Your fund's data, flowing in on its own.

A system of record is only as good as the data that reaches it. CapHive connects to the systems your fund already runs on, ingests the files it cannot connect to, and exposes an API for everything else.

How data arrives

Three routes into one ledger.

Most funds have a mix: two systems with a proper API, four that only produce files, and one internal tool nobody wants to replace. CapHive takes all three.

Direct connections, built to order

Name the bank, custodian or administrator and we will build the feed. CapHive is API-first underneath — everything the product does, it does through its own endpoints — so a new connection is a mapping exercise measured in weeks, not a re-platforming measured in quarters. Once it is live, positions, balances, transactions and documents land on a schedule and nobody exports anything by hand again.

Uploads and downloads, in the formats you already use

Data moves both ways, in the file formats your team works in today. Download a ready-made Excel template, fill it in and upload it back — commitments, capital events, KPIs, valuations, investor and portfolio company records all load in bulk. Bank statements, custodian reports and trial balances are mapped once, then every later file of that shape parses the same way. And everything in the platform comes back out again as Excel, CSV, PDF or Word.

API and webhooks

For internal tools, dashboards and anything bespoke, your engineers read and write directly — and subscribe to events instead of polling for changes.

Files & formats

Every list goes in, and every list comes out.

Nobody wants to retype a spreadsheet into a system, and nobody wants their numbers trapped once they are in one. CapHive treats the file as a first-class way to move data — in bulk, in both directions, in the formats finance teams actually send each other.

  • Excel and CSV uploads for bulk creation and updates — commitments, capital events, KPIs, valuations, investor and portfolio company records
  • A downloadable template behind every upload, pre-built with the right columns and picklists, so a file is never rejected for its shape
  • Excel and CSV exports on the lists and reports themselves, filtered exactly as you see them on screen rather than as a fixed extract
  • PDF and Word documents generated from your own templates — capital notices, statements, certificates and investor reports, in your wording and your branding
  • The original uploaded file kept alongside the data taken from it, so any figure can be traced back to the document it arrived on

API & webhooks

Everything in the platform, available to your engineers.

The API is how CapHive expects to be extended. If a workflow belongs in your own tooling, read the fund, portfolio and transaction data from CapHive rather than copying it.

  • REST API over the same objects the product uses — funds, investors, commitments, capital events, positions and documents
  • Webhooks for capital events, valuation changes, document signature and onboarding status
  • A sandbox environment with representative data, so integrations are built and tested away from live funds
  • Scoped API keys, so a credential can read portfolio data without touching investor records
  • Every API call attributed and logged alongside actions taken in the interface

Data quality

Data that arrives is data you can sign off on.

Ingestion is the easy half. The work is knowing that a number in an LP statement can be traced back to the file it came from, and that nothing was quietly double-counted on the way.

  • Validation rules applied on arrival — formats, dates, currencies, mandatory fields and sign conventions
  • Duplicate detection on restated files, re-sent statements and repeated transaction references
  • Exception queues, so a failed row is assigned to a person rather than lost in a log
  • Full lineage from source file to statement line, with the original document retained

Questions

What funds ask us first.

Do you support our bank?

Send us a sample statement and we will tell you which route applies. Where a bank publishes a connection or a host-to-host file drop, CapHive reads from it directly. Where it does not, the same statement you download today is ingested through a mapped template, and reconciliation works identically either way.

What if a system has no API?

Then it almost certainly produces a file, and that is enough. We map the file layout once — columns, headers, date and number formats — and every subsequent file of that shape is parsed, validated and reconciled without manual handling.

If the system produces neither a connection nor a file, data is entered in CapHive and the system stops being the source of record for that item.

Who owns the data?

You do. Your fund data, documents and the records derived from them remain yours. CapHive processes them to run the platform for you, and we do not treat your fund or investor data as an input to anything else.

How access is controlled
Can we export everything?

Yes. Structured data exports and the original uploaded documents are available on demand, in formats you can load elsewhere. Export is a standing capability, not a concession at the end of a contract.

How long does an integration take?

It depends on which route the system falls into. A mapped file template is usually the fastest, a direct connection depends on how quickly the counterparty grants access, and a bespoke API build moves at your engineering team's pace.

We scope each connection in discovery and give you a sequence, so the integrations that unblock your first close are done first.
