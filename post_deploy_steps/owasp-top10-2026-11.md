# Post-deploy steps — owasp-top10-2026-11

The OWASP Top 10 review 2026-11 release (PR #1918): the Critical/High fixes, Group A and Group B (M8, M11, M13,
M14). Written up in `docs/security/owasp_2026_11_release_note.md`. The archived designs are under
`openspec/changes/archive/2026-11-10-*`.

## production_in

### revoke-openai-key — Revoke the old OpenAI key at OpenAI (H1)
It was in a public JavaScript file; the code using it has been removed. Revoke it in the OpenAI dashboard (it is
one key for the company, so this is asked in production.in only).

## production

### enforce-flags — Switch on the inbound, webhook and host enforce flags (H2)
In this region's env file (`.env.production.in` or `.env.production.us`; never copy values between them), in the
order and with the checks in `docs/operations/security_review_2026_10_flags.md` (US: `SENDGRID_INBOUND_ENFORCE`
only after its step R4), then restart the app:
```
SENDGRID_INBOUND_ENFORCE=1
WEBHOOK_TOKEN_ENFORCE=1
ENFORCE_HOST_AUTHORIZATION=1
```

### formula-sandbox-enforce — Formula sandbox: log, then enforce (C1, H7, N1)
Run `formula_sandbox:audit` and fix what it lists, set `FORMULA_SANDBOX=log` through a month-end and a quarter-end,
then `FORMULA_SANDBOX=enforce` (flags doc, same order). Until it is on `enforce`, answer `skip on log since <date>`.

### security-events-mailbox — Check SECURITY_EVENTS_WEEKLY_TO (M11)
`SECURITY_EVENTS_WEEKLY_TO=support@caphive.com` must be set in this region's env file. If it is unset, the
Monday security pack is not sent.

### two-factor-end-unverified-access — Two-factor for support / super: end unverified access (M8)
First tell the support and super users that their next sign-in sets up two-factor. Then:
```
bin/rails two_factor_required:end_unverified_access              # dry run: prints the count
EXECUTE=1 bin/rails two_factor_required:end_unverified_access    # ends remember-me cookies + website tokens
```

### two-factor-report-zero — Two-factor report shows 0 without a verified method (M8)
Run `bin/rails two_factor_required:report` (counts only, never names). Answer `done` once it shows 0 without a
verified method; until then `skip <how many are left>`.

### payout-fields — Payout fields: dry run, then mark per firm after its admin agrees (M14)
```
bin/rails bank_detail_changes:propose_payout_fields                         # dry run: firm › form › field, counts only
EXECUTE=1 FIRM_ID=<id> bin/rails bank_detail_changes:propose_payout_fields  # one firm, only after its admin agrees
```
Send each listed firm's admin its list first. Marking changes no KYC and sends no email. Answer `done` once every
listed firm has agreed (and been marked) or declined.

### maker-checker-firms — Maker–checker: offer it to firms with two or more approvers (M13)
Customer success: switch it on per firm (entity form › Approvals) for the firms that agree. The design lists 7
firms whose users approve their own work today.

### onboarding-support-role — Onboarding user has the support role (N1)
Custom-field imports with Calculation fields are refused unless CapHive support uploads them. Give the onboarding
ops user the support role for clients whose forms include Calculation fields.

### kyc-release-note — Tell client KYC teams about bank-detail changes (M14)
Send the "Suggested message to client KYC teams" from `docs/security/owasp_2026_11_release_note.md`.

### grafana-thresholds — Tune the security alert thresholds (M12)
After a few weeks of real traffic, tune the Grafana thresholds for denied requests, throttles and failed sign-ins.
Until then answer `skip not yet — <date deployed>`.
