Extensibility

Add the fields your funds need. Today, not next release.

An administrator defines custom fields on a form type for any of 35 record kinds. Values are stored in that record's json_fields column, so adding a field never needs a schema change. Forms, detail pages, imports, exports, Report Builder, document templates, formulas and API responses all pick the field up.

Rules that come with each field

      

        
Validationmin/max length, min/max value, date range, selections count, regex pattern, formats (email, phone, URL, tax ids), uniqueness, max file size, custom error message

        
Conditionalshow a field only when another field eq / not_eq / contains / lt / lte / gt / gte a value

        
Multi-stepplace fields on steps 1–9 of onboarding and KYC forms, with your own step titles

        
Visibilityread-only for investors, internal-only, or visible to named users

        
Searchmark a field "Show in filter" and it becomes a list filter

        
Compliance setspre-built, jurisdiction-specific compliance field sets for KYC and instruments, maintained by CapHive

        
Variantsseveral tagged form types for one record kind, e.g. Individual vs Institutional commitments

Engines

    
How the platform computes on your data

    
Each engine reads named tables, runs rules you can see and change, and writes its results back as ordinary rows, with the working shown. Nothing is a black box: a generated ledger line records the formula that made it and a written explanation, and a ratio stores the cash flows it was computed from.

  

  

  







  

    
API

    
The same data, over JSON

    
The API runs on the same endpoints the application uses, under the same permissions, so an integration sees exactly what that user could see on screen. The OpenAPI 3 spec below is the published one; it is browsable live at app.caphive.com/api-docs.

  

  

    
Bearer tokens
Server-to-server
Send Authorization: Bearer <token> on every request. Tokens are scoped to your organisation's account.

    
OAuth2 · OpenID Connect
Client credentials
CapHive is an OAuth2/OIDC provider. Your system exchanges a client id and secret for a scoped, time-limited access token.

    
MCP server
AI assistants
A Model Context Protocol server lets AI clients such as Claude query funds, commitments, calls, ratios, portfolio and KPIs under your permissions, with filters validated against a published ontology.

    
Bulk
Spreadsheet import & dumps
Import templates load any record kind, custom fields included. Scheduled per-organisation SQLite dumps hand you a portable copy of your data.

  

  

    

    

  







  

    
System of record vs data lake

    
Keep the lake downstream

    
A data lake is good at storing rows. Running a fund needs more than storage: the data has to mean something, the numbers have to be computed the same way every quarter, corrections have to leave a trail, and each LP may see only their own slice. Putting a lake first means building all of that yourself. Put CapHive first, and feed your lake from it.
