# Release Notes — V9.2.98
**Released: 22 September 2026**

---

## What's New

### See how any calculated figure was worked out, term by term
The account entry page now has a "How this was worked out" card in place of the old explanation box. It breaks the figure into the terms its rule actually used — the parts of a sum, the factors of a product, the named values it referenced — each shown with the value recorded when the run happened. Where a term is itself another calculated figure, you can open it and see that figure's own breakdown, and keep going down the chain. The card says the lines add up only where the rule is genuinely a sum; a rule that multiplies or divides says plainly that its lines are the figures it worked from, not parts of a total. Where a rule could not be read at all, it says so rather than making a claim.

### Trace where a run's numbers come from, across the whole run
The Account Entries Period Report has a new Dependencies tab for a chosen allocation run. Search for any figure name, or switch on "Top-level numbers only" to see the figures the run produced but nothing else consumed, then expand a row to see everything it was built from — and expand those in turn, as deep as the run goes, with no waiting between levels. Figures read from an earlier period, and amounts that are subtracted rather than added, are marked as such.

### Feeder Fund is now part of the commitments upload and export
The commitments upload always accepted a Feeder Fund column, but nothing advertised it. It is now in the downloadable template with the same guidance as every other column, and the commitments export shows the feeder fund name next to the fund wherever a folio has one. Files built from the older template still upload. An Update Only row from a sheet with no Feeder Fund column now leaves an existing feeder fund alone — previously it could clear it without saying so. A blank cell in a sheet that does have the column still clears it, as you would expect.

### Upload document questions from a spreadsheet
Document questions — the questions AI answers when it reads an uploaded document — could only be added one at a time. You can now download them, edit the sheet, and upload it back. A row that keeps its Id updates the question it came from, so correcting the wording is an edit rather than a second question; a row without an Id creates a new question and refuses to create a duplicate.

### Deleted records now show who deleted them
The deleted records page has a new Deleted By column naming the person who deleted each row, with their email, and marking the account as deactivated if they have since left. Rows removed by a background job, an import, or as a knock-on from a parent record read "System", with a note explaining why no name is recorded. Deletions carried out by background jobs — bulk deletes, imports, scheduled clean-up — are now attributed to the person who started the job in the audit trail, instead of appearing as unattributed. The page also loads faster, as it no longer looks up folders one row at a time.

## Improvements

### Extra spaces in dropdown choices no longer hide answers
A custom field's choices are typed as one comma-separated list, so an admin typing "Individual, HUF, LLP" created a choice whose stored value carried the leading space. The answer looked right on screen but no longer matched anything exactly: grid and register filters skipped those records, custom field searches missed them, and a conditional field could stay hidden while the form still insisted it was required. Spaces around each choice are now ignored, both on screen and when the list is saved, and both sides of a conditional rule are compared with spaces trimmed so answers saved earlier resolve correctly. A deliberate empty first choice still works — a dropdown that starts blank stays blank. A one-time clean-up of choices and answers already stored runs with this release; where trimming would make two choices identical the field is left alone and reported, rather than one of them being guessed at.

### Folder access grants no longer offer checkboxes that did nothing
The Grant Access form for a folder carried two checkboxes that could not do what they said. "Send Notification" could never send an email for a folder, so the grant only recorded that the notification was skipped. "Apply to files and sub folders" was in practice required, not optional: leaving it unticked gave the stakeholder a data room they could open with no files inside, while files uploaded later did appear — so the folder looked half-shared with no explanation. Both boxes are gone from folder grants, and folder access now always applies to the files and sub-folders inside. Document-level and deal-level grants keep their notification box, which works as before. Note that folder grants made earlier without the tick still have files that were never shared; re-granting access on the folder fixes those.

## What to Do

| If you use...   | Action                              |
|------------------|-------------------------------------|
| Account entry figures | No action needed. Open any calculated entry to see "How this was worked out", and open a line to follow the chain further. |
| Allocation run reviews | No action needed. Use the Dependencies tab on the Account Entries Period Report for the run you are reviewing. |
| Commitments upload | Download the latest commitments template if you want the Feeder Fund column and its guidance. Older files still upload. |
| Document questions | No action needed. Download the questions, edit the sheet and upload it back to change several at once. |
| Deleted records | No action needed. |
| Custom field dropdowns | No action needed. If a field is reported as having two choices that are the same once spaces are removed, correct that list by hand. |
| Folder access rights | No action needed for new grants. For folders shared earlier where the stakeholder cannot see older files, grant access on the folder again so the existing files are included. |
