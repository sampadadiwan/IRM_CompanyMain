# Release Notes — V9.2.52

**Released: 5 June 2026**

---

## What's New

### Fund Unit Settings Export — Download all funds at once

You can now download fund unit settings across all funds in your entity in a single Excel export. Previously this was limited to one fund at a time. The export also includes GP unit indicators, giving you a complete picture of unit configurations in one file.

---

## Improvements

### DocuSign Reliability — Clearer errors and fewer silent failures

The DocuSign e-signing workflow has been significantly hardened. Your team will now see actionable alerts when a signing request fails or is cancelled, rather than the process silently stopping. Token authentication has been restructured to work correctly across staging and production environments, and temporary file handling is now more robust to prevent edge-case failures.

### Financial Calculation Precision — Accurate to the cent (and beyond)

Money calculations throughout the platform now use infinite precision, eliminating rounding errors that could accumulate in fund ratio and portfolio calculations. Division operations also apply consistent rounding, so computed values in ratio runs and multi-fund scenarios are exact.

### Fund Ratio Aggregate Display — Improved layout and accuracy

The fund ratio aggregate widget has been updated with a cleaner layout and a fix for a decimal display error. Figures shown in aggregate ratio views now reflect the correct values.

### Capital Call Import Validation — Call basis now enforced

When importing capital calls, the system now validates that the call basis field is present. Records missing this value are flagged early in the import process rather than failing silently downstream, making it easier to catch and correct data issues before they affect your books.

### Incoming Email Assignment — Case-insensitive owner matching

Incoming emails are now matched to their owners using case-insensitive email address comparison. Emails were occasionally unassigned when the sender's address used different capitalisation than what was on file — this is now resolved.
