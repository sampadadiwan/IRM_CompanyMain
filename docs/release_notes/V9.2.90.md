# Release Notes — V9.2.90
**Released: 25 August 2026**

---

## What's New

### Compare a KPI to its own last report — no extra upload needed
When setting up a red/amber/green rule for a KPI, you can now choose "Prior period" as the comparator instead of pointing at a separately tagged report. CapHive automatically compares the new figure against whichever report for that same KPI came in most recently before it — whatever your reporting cadence is — so straightforward period-over-period rules, like flagging a revenue drop month over month, no longer need a second upload just to make the comparison.

### RAG status now shown on a KPI's own page
A KPI's red/amber/green flag and a note on the rule behind it now appear directly on that KPI's own page, not just in mapping-level views.

### Undo an approval and re-check its RAG status
If a KPI was approved by mistake, authorized users can now unapprove it. This clears its red/amber/green flag and automatically re-checks any other KPI that was comparing itself against that figure, so nothing downstream is left showing a stale flag.

### RAG recompute now runs in the background
Recomputing red/amber/green status for every approved KPI under a mapping — after adding or changing a rule — no longer ties up your browser while it runs. You'll get a notification once it's done instead of waiting on the page.

---

## Improvements

### More trustworthy RAG flags
Red/amber/green comparisons now only ever use figures that have actually been approved. A not-yet-confirmed value can no longer be flagged itself, or quietly used as the comparison figure for someone else's KPI, before a fund has signed off on it.

---

## What to Do

| If you use...            | Action                                                                                   |
|---------------------------|-------------------------------------------------------------------------------------------|
| KPI RAG rules             | Try "Prior period" next time you set up a month-over-month or quarter-over-quarter rule. |
| KPI approvals             | No action needed. Use "Unapprove" on a KPI's page if one was confirmed by mistake.       |
| KPI Mapping RAG recompute  | No action needed. You'll now get a notification instead of waiting for the page to reload. |
