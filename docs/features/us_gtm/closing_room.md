# Closing Room

**Approach:** Enhance existing `KycOnboardingAgent` + extend `onboarding_completed` signal — NOT a new model
**Phase:** P1 — requires P0 US checks (tax forms, qualification) to be meaningful

---

## Revised Understanding

The original spec proposed a new `FundClosing`, `ClosingRoomStatus`, and `ClosingException` model hierarchy. After examining the codebase, this is unnecessary. The platform already has most of what a Closing Room requires:

| What the Closing Room needs | What already exists |
|-----------------------------|-------------------|
| Per-investor readiness signal with issue breakdown | `KycOnboardingAgent` → `SupportAgentReport` with field_issues, document_issues, AML status; `onboarding_status` badge already rendered on KYC records |
| KYC verified (all data + docs kosher) | `InvestorKyc.submission_status = verified`; bank fields are **required** on the model so verified implies bank details present |
| Bank details confirmed | Bank fields (`bank_name`, `bank_account_number`, `ifsc_code`) are required KYC fields; `bank_verification_response` stores verification evidence |
| Cross-investor status view | Existing Onboarding Report (`funds/dashboard/onboarding_report.html.erb`) with `onboarding_completed` flag and `lp_onboarding_complete`/`lp_onboarding_incomplete` scopes |
| AML check | `KycOnboardingAgent` auto-triggers `GenerateAmlReportJob` when no blocking issues remain |
| Expiry / stale KYC detection | `check_expiry_status` step in the agent; `expired?` scope; configurable warning thresholds |

**What is genuinely new for a US closing:**
1. Subscription document e-sign status — not currently checked by the agent
2. US-specific checks: tax form, investor qualification, side letter — new for US but fit naturally as new agent steps
3. A "close the closing" action — admitting all ready investors in one batch, generating binders, exporting to fund admin

The right architecture: **extend `KycOnboardingAgent` with US-specific steps** and **enhance the existing Onboarding Report** with the closing action. No new model hierarchy.

| Persona | When | What They Need |
|---------|------|----------------|
| **COO / Head of Operations** | Every day during a fundraising close | See which investors' KYCs are verified and which have blocking issues; understand what dimension is blocking each investor |

| **CFO** | Pre-admission | Confirm commitment amounts and equalization; trigger the batch admission action |
| **Fund Administrator** | Receiving the close | Receive structured data export and closing binder at the point of admission |

## How KYC Verification Maps to Closing Readiness

When `InvestorKyc.submission_status = verified`:
- All required model fields are present: `full_name`, `address`, `birth_date`, `PAN` (or US tax ID), `bank_name`, `bank_branch`, `bank_account_type`, `bank_account_number`, `ifsc_code` (or US routing/account)
- All required File-type custom fields (documents) are uploaded — enforced by `check_required_file_type_custom_fields`
- `KycOnboardingAgent` has run: field completeness ✓, document presence ✓, document validity ✓, field-to-document consistency ✓
- AML report has been triggered (or is in progress)
- No blocking issues in `SupportAgentReport`

This means **verified KYC = the LP's identity, entity, and bank details have been checked and are kosher**. The Closing Room does not need to re-verify these — it reads `submission_status`.

For US funds, "verified" must additionally cover:
- US tax form collected (W-9/W-8) — added as a KycOnboardingAgent step
- Investor qualification confirmed (AI/QP/QC) — added as a KycOnboardingAgent step
- Subscription agreement e-signed — added as a KycOnboardingAgent step

## Build Approach

### Step 1: Add US Check Steps to `KycOnboardingAgent`

Extend the existing pipeline with three new steps after `check_expiry_status`:

```ruby
# In KycOnboardingAgent
step :check_us_tax_form_status      # New for US
step :check_subscription_doc_status # New for US
step :check_investor_qualification  # New for US
step :check_side_letter_status      # New for US (Phase 2)
```

**`check_us_tax_form_status`:**
- Only runs when `entity.us_market_enabled?` (a flag we add to EntitySetting)
- Reads `investor_kyc.json_fields["form_status"]` (set by the tax form expiry job — see `us_tax_forms.md`)
- Reads whether the required US tax form File field has an uploaded document
- Issues: `{ type: :us_tax_form_missing, severity: :blocking }` or `{ type: :us_tax_form_expired, severity: :blocking }`

**`check_subscription_doc_status`:**
- Reads `ESignature` records on documents belonging to the investor's capital commitment
- Checks whether a document tagged as a subscription agreement has `status = signed` or `status = completed`
- Issues: `{ type: :subscription_docs_unsigned, severity: :blocking }`

**`check_investor_qualification`:**
- Reads `InvestorQualification` records for the investor + fund (from the Qualification Engine — see `investor_qualification_engine.md`)
- Issues: `{ type: :qualification_pending, severity: :blocking }` or `{ type: :qualification_exception, severity: :requires_approval }`

**`check_side_letter_status`** (Phase 2):
- Reads `SideLetter` record for the investor + fund (from `side_letter_obligations.md`)
- If a side letter is required but not executed: `{ type: :side_letter_pending, severity: :blocking }`

### Step 2: Enhance `SupportAgentReport` Display for US

The existing `_kyc_onboarding_agent.html.erb` already renders a badge with counts for missing fields, missing docs, invalid docs, and mismatches. Add US-specific cards:

```ruby
# New cards in the badge partial
{ icon: "ti ti-file-invoice",   subtitle: "Tax Form",       value: ..., type: :boolean },
{ icon: "ti ti-writing-sign",   subtitle: "Subscription",   value: ..., type: :boolean },
{ icon: "ti ti-user-check",     subtitle: "Qualification",  value: ..., type: :boolean }
```

### Step 3: Enhance the Onboarding Report as the Closing Dashboard

The existing `onboarding_report.html.erb` already shows per-commitment onboarding status. Enhance it to become the Closing Room view:

**Add to the report:**
- Summary bar: Ready / Blocked / Admitted counts with committed amounts
- Filter by: `fund_close` (to scope to a specific tranche), status
- Add "onboarding_status badge" column (already exists via `ONBOARDING_AGENT_REPORT_COLUMNS`)
- Add "Admit" button per investor (visible when `KycOnboardingAgent` report has no blocking issues)
- Add "Admit All Ready" bulk action

### Step 4: Auto-Set `onboarding_completed` from Agent Result

Currently `onboarding_completed` is set manually. For US closings, auto-set it when:
- `InvestorKyc.submission_status = verified`
- `SupportAgentReport` has zero blocking issues (including new US steps)

```ruby
# In KycOnboardingAgent, after generate_progress_reports:
def auto_complete_onboarding(ctx, investor_kyc:, **)
  report = ctx[:support_agent_report]
  all_issues = report.json_fields.values.flatten
  has_blocking = all_issues.any? { |i| i["severity"] == "blocking" }

  if !has_blocking && investor_kyc.submission_verified?
    investor_kyc.capital_commitments.update_all(onboarding_completed: true)
  end
end
```

### Step 5: Closing Binder Generation (new — lightweight)

When `onboarding_completed` flips to `true` on a commitment, trigger a background job:

```ruby
# ClosingBinderJob
# Collects: all documents from investor_kyc.documents folder,
#           SupportAgentReport summary PDF,
#           InvestorQualification summary
# Zips them, stores as a Document on the commitment with name "Closing Binder"
```

This replaces the entire `FundClosing`, `AdmissionRecord`, `ClosingRoomStatus` model hierarchy from the original spec with a single background job triggered by an existing boolean flag.

## Functional Requirements

1. `check_us_tax_form_status`, `check_subscription_doc_status`, and `check_investor_qualification` steps only run when `entity.us_market_enabled? = true` — no effect on non-US entities
2. `onboarding_completed` is auto-set to `true` by the agent when all checks pass and `submission_status = verified`; it can still be manually overridden by an Approver-role user
3. The "Admit All Ready" bulk action sets `onboarding_completed = true` on all commitments whose linked KYC has no blocking issues; it is gated behind the Approver role
4. Closing binder generation is triggered by the `onboarding_completed` transition; re-generation available on demand
5. `KycOnboardingAgent` runs on the same triggers as today: scheduled (daily) and event-driven (on KYC update, document upload, e-sign status change)
6. Fund admin data export is triggered from the Onboarding Report "Export" action — no new export model needed; uses the existing Report Builder + Fund Admin Exchange format

---

## What the Closing Room Is Now

Rather than a new feature, the Closing Room is:

> **The existing Onboarding Report + KycOnboardingAgent, enhanced with US-specific check steps, an upgraded summary view, and a batch admit action.**

The pipeline is: `KycOnboardingAgent` checks the investor → produces `SupportAgentReport` → `onboarding_status` badge reflects readiness → Onboarding Report aggregates across all investors → Admit action flips `onboarding_completed` → Closing Binder job generates evidence package.
